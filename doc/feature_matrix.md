# Feature matrix

| Area | Status | Notes |
| --- | --- | --- |
| Runtime capabilities | Supported | Dart reports current feature gates, ABI version, upstream commit, and native build-flag metadata from a built native bridge. |
| Typed Dart configs/errors | Supported | Public configs and exceptions compile and are tested. |
| RAG primitives | Supported | Character/token splitting, embedding/retriever/reranker interfaces, persistable in-memory vector search, validated retriever/reranker results, typed citations, exact tokenizer-backed context budgeting, and complete chat-template token budgeting are Dart-only and tested. |
| Native bridge | Experimental | ABI version, capability struct, backend init/free, model handle lifecycle, context lifecycle, generation handle lifecycle, model info, tokenization, detokenization, allocation-free thread-local last-error reporting, and configurable native logging exist with native smoke tests. Platform linker controls export only the `llama_dart_*` C ABI and keep statically linked upstream symbols private; host CTest audits the resulting dynamic symbol table. Logging is silent by default; opt-in severity filtering feeds a process-wide bounded queue that Dart drains into immutable typed records without native-thread callbacks into Dart. |
| Model loading | Experimental | Bridge can call `llama_model_load_from_file`; Dart can validate local model files, check GGUF magic bytes, verify SHA-256 digests, explicitly delete local model files, configure mmap/mlock/tensor-check loading flags and GPU layer count, inspect core model info, query the model architecture, tokenizer metadata, file type/quantization name, and NextN/MTP layer count, read size-bounded GGUF metadata, or load an engine in a worker isolate and free the handle. Lightweight inspection reads standard scalar architecture hparams directly from GGUF metadata without allocating model weights. Apple builds embed Metal; auto/CPU/Metal device selection and effective-backend inspection are exposed. Vulkan selection works only with a Vulkan-enabled custom bridge. |
| Context lifecycle | Experimental | Bridge can create/free/reset/warm/prefill/shift `llama_context` handles. `LlamaEngine.load` owns model/context handles in a worker isolate and exposes context/batch/ubatch/thread tuning plus typed K/V cache data types, KV offload, Flash Attention, full-size SWA cache, and unified-cache controls for target and draft/MTP contexts. Explicit CPU mode disables both operation and KV offload. `warmUp()` primes empty target and draft/MTP contexts without retaining session state. `prefill()` evaluates reusable text prefixes without sampling, reports typed timing/token telemetry, and automatically adds model special tokens only to an empty context. `contextInfo()` reports actual native dimensions, applied cache settings, used tokens, and dynamic shift support. `shiftContext()` transactionally removes an explicit or automatic old-token range from target and draft caches while preserving a prefix and recent tail; multimodal, recurrent/non-shiftable, active-generation, and legacy snapshots without token history are rejected. `saveState()`/`restoreState()` use a checksummed versioned envelope containing target, draft/MTP, optional strategy-private, position, and token-history state; restore validates the full envelope before mutation and rolls back context sections on failure. Pending commands and streams observe unexpected worker exit instead of hanging. A non-retaining Dart finalizer requests best-effort cancellation/worker cleanup for leaked engines; explicit `close()` remains required. Legacy target-only snapshots remain readable by non-model-backed contexts. |
| Tokenization | Experimental | `LlamaEngine.tokenize`, `countTokens`, and `detokenize` reuse the engine's worker-owned model and serialize with inference. Static `LlamaTokenizer` helpers use a temporary worker/vocab-only model for pre-engine workflows. Both paths call upstream `llama_tokenize` and `llama_detokenize`; model inspection exposes special-token metadata. |
| Chat templates | Experimental | `LlamaEngine.formatChat`, `countChatTokens`, and `chatTemplateCapabilities` reuse its loaded model. Static `LlamaChatTemplate.format`, `countTokens`, and `capabilities` use one temporary model load per operation, and `LlamaEngine.chat` uses the same upstream templates for generation. Plain text uses `llama_chat_apply_template`; tool-aware requests use pinned `common_chat_templates_apply`, with model-specific capability inspection and typed unsupported errors. |
| Text generation | Experimental | `LlamaEngine.complete` and `chat` stream decoded chunks from a native generation handle in the worker isolate, with final token/time-to-first-token/tok/s telemetry plus speculative draft/accepted counts and draft/verification timings. A start/step/dispose protocol keeps at most one bounded native batch in flight; `streamChunkTokens` coalesces events, subscription pause/resume gates later steps, cancellation disposes paused work, and parallel requests serialize on one context. `continueCompletion()` samples directly from prefetched, generated, or restored non-empty state. Fresh unconstrained sampler chains are seeded from bridge token history so repeat/presence/frequency penalties span incremental requests. Empty contexts add model special tokens automatically, continued contexts do not duplicate them, and chat templates parse trusted model control tokens. Stop strings use native byte holdback and custom stop token IDs terminate before decoding or emission. |
| Sampling | Experimental | Temperature, top-k, top-p, min-p, typical-p, repeat/presence/frequency penalties, Mirostat v1/v2, seed, stop strings, and model token IDs are wired to upstream sampler chains and vocabulary semantics. |
| Structured output | Experimental | Runtime capabilities expose this gate. `GenerationConfig.grammar` passes GBNF rules to upstream `llama_sampler_init_grammar`, `GenerationConfig.jsonMode` uses the pinned JSON GBNF, and `GenerationConfig.jsonSchema` snapshots the schema and converts it off the caller isolate through pinned upstream `json_schema_to_grammar`, including local `$defs`/`$ref` and the schema features supported by that commit. Invalid or upstream-unsupported schemas return typed errors. The standalone `llamaJsonSchemaGrammar()` function remains a deterministic pure-Dart common-subset converter. External references remain unsupported upstream. |
| Function/tool calling | Experimental | Active tools are rendered and constrained through pinned upstream Jinja chat plans, including lazy grammar triggers, generation prefixes, additional stops, parser state, template capability gates, named/required/none/auto choice, and parallel-call gating. Terminal `GenerationChunk.assistantMessage` carries normalized typed calls with stable IDs; assistant call and correlated tool-result history round-trip through `ChatMessage`. Tool execution remains app-owned. Pinned Gemma 4 vocabulary fixtures cover rendering and parser plans; an opt-in checksum-pinned official Qwen2.5 0.5B fixture covers weighted named-call generation, typed parsing, generated IDs, result history, and a final assistant response. See [tool_calling.md](tool_calling.md). |
| Embeddings | Experimental | `LlamaEmbeddings.embedText` and `embedTexts` run worker-isolate embedding jobs and return optionally normalized pooled upstream sequence embeddings. Single results use `Float32List`; batches use row-major `EmbeddingBatch` storage with one flat `Float32List`, zero-copy vector views, and normalization/pooling metadata. Multimodal and speculative decoding settings are rejected for embedding contexts. An opt-in checksum-pinned Apache-2.0 MiniLM GGUF test covers real model inspection, single embedding, same-context batch embedding, deterministic output, normalization, and semantic ranking without bundling weights. |
| Native reranking | Experimental | `LlamaReranking.scorePair`, `scoreDocuments`, and `LlamaReranker` use upstream rank pooling with rerank prompt formatting and configurable special-token parsing. `LlamaReranker` validates and snapshots candidate chunks before native scoring. Multimodal and speculative decoding settings are rejected for reranking contexts. An opt-in checksum-pinned Apache-2.0 Jina tiny reranker test covers real pair scoring, same-context batches, deterministic semantic ordering, and RAG candidate reordering without bundling weights. |
| Multimodal | Experimental | Matching `mmprojPath` files load through pinned upstream `mtmd`. Image/audio file and encoded-byte parts are preprocessed in the worker isolate, context info reports model-specific vision/audio support, and each request is bounded to 64 inputs of at most 64 MiB each. Opt-in checksum-pinned TinyGemma3 CIFAR and official Qwen3 ASR fixtures cover real model/mmproj loading, deterministic file/byte image classification and audio transcription, telemetry, and cleanup. Video stays unsupported because upstream's helper requires external ffmpeg tools. See [multimodal.md](multimodal.md). |
| LoRA | Experimental | `LlamaEngine` can load, list, globally scale, and unload upstream LoRA adapters by opaque id. `GenerationConfig.loraScales` can select an exact adapter/scale set for one request; `null` uses global scales and an empty map disables all adapters. Worker cleanup restores global scales after success, cancellation, or failure. An opt-in checksum-pinned MIT base/adapter pair verifies real load, observable generation changes, scale zero/one, request disable and restoration, unload, and baseline recovery. See [lora.md](lora.md). |
| Speculative decoding/MTP | Experimental | `NGramSpeculation` exposes pinned upstream `ngram-simple`, `ngram-map-k`, and `ngram-map-k4v`; `NGramModSpeculation` exposes configurable match/minimum/maximum draft lengths; and request-local `NGramCacheSpeculation` uses an in-memory cache without unsafe external cache files. Synthetic drafts plus weighted output/state equivalence cover all five draftless strategies. `DraftModelSpeculation`, `Eagle3Speculation`, `DFlashSpeculation`, and `MtpSpeculation` use the same `common_speculative` layer, including integrated or separate MTP heads, strategy compatibility checks, cooperative draft-context cancellation, rejected-tail removal, configurable draft limits, and composite state snapshots. `LlamaModelInfo.nextnLayerCount` exposes model MTP metadata. Model-backed speculation cannot share an mmproj context, and media-bearing requests reject every speculative strategy. Stop-string or stop-token requests fall back to ordinary decoding. Opt-in checksum-pinned fixtures verify ordinary TinyLlama draft-model, Qwen3 1.7B EAGLE-3, and integrated Qwen3.5 MTP output equivalence, accepted-token telemetry, and cleanup. DFlash has configuration/native validation but remains upstream-dependent because no compatible fixture is pinned here. |
| Native-assets packaging | Experimental | A CMake-backed build hook emits a bundled `llama_dart_bridge` code asset for Dart/Flutter native-assets builds. Host smoke coverage exists, supported-ABI Android debug and release APK packaging pass from `example/`, iOS config-only generation passes, and the bridge cross-compiles directly for iOS 15 arm64 with embedded Metal. Full Flutter iOS builds are blocked in this workspace because Xcode reports the iOS 26.5 platform component as unavailable; device smoke tests remain pending. |
| Examples | Experimental | `example/dart_cli/chat.dart` demonstrates local chat with an app-supplied GGUF model, `embeddings.dart` exercises real flat batch embeddings, `local_rag.dart` demonstrates model-free local RAG primitives, and image/audio CLIs exercise matching mmproj files. The mobile-first Flutter `example/` selects app-owned GGUF/mmproj/image files, loads and unloads an engine, streams cancellable text/image chat, resets full-history context, and reports capabilities and telemetry while also validating native-assets packaging. |
