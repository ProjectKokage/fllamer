# Feature matrix

| Area | Status | Notes |
| --- | --- | --- |
| Runtime capabilities | Supported | Dart reports current feature gates, ABI version, upstream commit, and native build-flag metadata from a built native bridge. |
| Typed Dart configs/errors | Supported | Public configs and exceptions compile and are tested. |
| RAG primitives | Supported | Character/token splitting, embedding/retriever/reranker interfaces, persistable in-memory vector search, validated retriever/reranker results, typed citations, exact tokenizer-backed context budgeting, and complete chat-template token budgeting are Dart-only and tested. |
| Native bridge | Experimental | Current ABI 42, capability struct, backend init/free, model handle lifecycle, context lifecycle, generation handle lifecycle, model info with cached maximum decoded token-piece bytes, tokenization, detokenization, allocation-free thread-local last-error reporting, and configurable native logging exist with native smoke tests. Platform linker controls export only the `llama_dart_*` C ABI and keep statically linked upstream symbols private; host CTest audits the resulting dynamic symbol table. Logging is silent by default; opt-in severity filtering feeds a process-wide bounded queue that Dart drains into immutable typed records without native-thread callbacks into Dart. |
| Model loading | Experimental | Bridge can call `llama_model_load_from_file`; Dart can validate local model files, check GGUF magic bytes, verify SHA-256 digests, explicitly delete local model files, configure mmap/mlock/tensor-check loading flags and GPU layer count, inspect core model info, query the model architecture, tokenizer metadata, file type/quantization name, and NextN/MTP layer count, read size-bounded GGUF metadata, or load an engine in a worker isolate and free the handle. The public mmap/mlock booleans map exactly to upstream's none, mmap, mlock, and mmap+mlock load modes. Integrated MTP tensors are requested only for target-owned MTP heads; ordinary and sidecar-backed loads keep upstream's reduced-memory default. Lightweight inspection reads standard scalar architecture hparams directly from GGUF metadata without allocating model weights. Apple builds embed the pinned upstream Metal backend; auto/CPU/Metal device selection and effective-backend inspection are exposed. Automatic selection resolves to an explicit CPU device with zero GPU layers on Apple Simulator targets; explicit Metal remains available only as a diagnostic request there, while physical-device Metal validation remains separate. Linux and Windows native-assets builds compile Vulkan by default while retaining explicit CPU selection. Android remains CPU-only by default and exposes an opt-in Vulkan build variant. One final-source Adreno 750 Debug-harness run selected Vulkan, matched a bounded CPU oracle, and completed cancellation/reset/recovery/repeat-dispose checks. On Qualcomm proprietary drivers, Q4_K uses a restricted safe route and Q5_K/Q6_K matrix work falls back to CPU. This is experimental, device-specific evidence only; Android Vulkan remains unqualified and is not a performance claim. |
| Context lifecycle | Experimental | Bridge can create/free/reset/warm/prefill/shift `llama_context` handles. `LlamaEngine.load` owns model/context handles in a worker isolate and exposes context/batch/ubatch/thread tuning plus typed K/V cache data types, KV offload, Flash Attention, full-size SWA cache, and unified-cache controls for target and draft/MTP contexts. Explicit CPU mode disables both operation and KV offload. `warmUp()` primes empty target and draft/MTP contexts without retaining session state. `prefill()` evaluates reusable text prefixes without sampling, reports typed timing/token telemetry, and automatically adds model special tokens only to an empty context. `contextInfo()` reports actual native dimensions, applied cache settings, used tokens, and dynamic shift support; a quantized V cache reports Flash Attention as enabled after upstream promotes an `auto` request. `shiftContext()` transactionally removes an explicit or automatic old-token range from target and draft caches while preserving a prefix and recent tail; multimodal, recurrent/non-shiftable, active-generation, and legacy snapshots without token history are rejected. `saveState()`/`restoreState()` use a checksummed versioned envelope containing target, draft/MTP, optional strategy-private, position, and token-history state; restore validates the full envelope before mutation and rolls back context sections on failure. Pending commands and streams observe unexpected worker exit instead of hanging. A non-retaining Dart finalizer requests best-effort cancellation/worker cleanup for leaked engines; explicit `close()` remains required. Legacy target-only snapshots remain readable by non-model-backed contexts. |
| Tokenization | Experimental | `LlamaEngine.tokenize`, `countTokens`, and `detokenize` reuse the engine's worker-owned model and serialize with inference. Static `LlamaTokenizer` helpers use a temporary worker/vocab-only model for pre-engine workflows. Both paths call upstream `llama_tokenize` and `llama_detokenize`; model inspection exposes special-token metadata. |
| Chat templates | Experimental | `LlamaEngine.formatChat`, `countChatTokens`, `chatTemplate`, and `chatTemplateCapabilities` reuse its loaded model. Loaded-engine `modelInfo` and `modelMetadata` avoid reopening the configured path. Static `LlamaChatTemplate` helpers use a temporary model load, and `LlamaEngine.chat` uses the same selected template for generation. `LlamaModelConfig.chatTemplate` is an explicit override; otherwise an embedded GGUF template is required. Missing, blank, invalid UTF-8, and oversized templates fail closed instead of falling back to ChatML. Ordinary chat tries `llama_chat_apply_template` first and, only when that formatter reports unsupported, retries through pinned `common_chat_templates_apply`; tool-aware requests use the common planner directly. Nullable `GenerationConfig.enableThinking` selects request-level template behavior: an explicit value forces native Jinja chat planning and forwards typed `enable_thinking` without a model reload, while `null` retains legacy formatter selection. When explicit Off has paired template reasoning markers, native sampling additionally applies a zero reasoning budget so a stray reasoning start is forced closed without truncating the public suffix; markerless templates retain template-only behavior. `enableThinking: true` rejects app-supplied raw grammar, JSON mode, and JSON schema because those constraints would otherwise apply to hidden reasoning; planner-owned tool grammar remains supported, and strict terminal parsing keeps reasoning separate from the normalized assistant value. Raw completion and continuation reject explicit thinking control. Fallback generation retains structured-output constraints and template stops, while strict terminal parsing remains limited to tool/history plans. |
| Text generation | Experimental | `LlamaEngine.complete` and `chat` stream decoded chunks from a native generation handle in the worker isolate, with final token/time-to-first-token/tok/s telemetry plus speculative draft/accepted counts and draft/verification timings. Terminal chunks expose a typed stop reason for end-of-generation, stop sequences, stop tokens, or maximum-token exhaustion. A start/step/dispose protocol keeps at most one bounded native batch in flight; `streamChunkTokens` coalesces text and subscription pause/resume gates later steps. Content-free `GenerationChunk.generatedTokens` events report increasing counts from completed native calls independently of coalescing, without completing a batch or inventing progress during blocked native work. A second active or pending stream and other context work are rejected with a typed generation error instead of being queued. Stream cancellation awaits native-handle disposal and a context reset before releasing the engine slot, preventing partial or stale generation state from reaching the next request. `continueCompletion()` samples directly from successfully prefetched, generated, or restored non-empty state. Fresh unconstrained sampler chains are seeded from bridge token history so repeat/presence/frequency penalties span successful incremental requests. Empty contexts add model special tokens automatically, continued contexts do not duplicate them, and chat templates parse trusted model control tokens. Stop strings use native byte holdback and custom stop token IDs terminate before decoding or emission. |
| Sampling | Experimental | Temperature, top-k, top-p, min-p, typical-p, repeat/presence/frequency penalties, Mirostat v1/v2, seed, stop strings, model token IDs, and model-provided `tokenizer.ggml.suppress_tokens` are wired to upstream sampler chains and vocabulary semantics. |
| Structured output | Experimental | Runtime capabilities expose this gate. `GenerationConfig.grammar` passes GBNF rules to upstream `llama_sampler_init_grammar`, `GenerationConfig.jsonMode` uses the pinned JSON GBNF, and `GenerationConfig.jsonSchema` snapshots the schema and converts it off the caller isolate through pinned upstream `json_schema_to_grammar`, including local `$defs`/`$ref` and the schema features supported by that commit. Invalid or upstream-unsupported schemas return typed errors. The standalone synchronous `llamaJsonSchemaGrammar()` compatibility helper delegates to that same pinned native converter. External references remain unsupported upstream. |
| Function/tool calling | Experimental | Active tools are rendered and constrained through pinned upstream Jinja chat plans, including lazy grammar triggers, generation prefixes, additional stops, parser state, template capability gates, named/required/none/auto choice, and parallel-call gating. Gemma 4 uses the pinned upstream generic argument grammar, which does not enforce each tool's parameter schema during generation. Every terminal parsed call is validated against its matching schema before exposure. Terminal `GenerationChunk.assistantMessage` carries normalized typed calls with stable IDs; assistant call and correlated tool-result history round-trip through `ChatMessage`. Tool execution remains app-owned. Pinned Gemma 4 vocabulary fixtures cover rendering, parsing, and post-parse schema validation; an opt-in checksum-pinned official Qwen2.5 0.5B fixture covers weighted named-call generation, typed parsing, generated IDs, result history, and a final assistant response. See [tool_calling.md](tool_calling.md). |
| Embeddings | Experimental | `LlamaEmbeddingEngine` keeps one worker-owned embedding context loaded for repeated tokenization, metadata inspection, and embedding batches. The one-shot `LlamaEmbeddings.embedText` and `embedTexts` helpers remain available. Results are optionally normalized pooled upstream sequence embeddings: single results use `Float32List`; batches use row-major `EmbeddingBatch` storage with one flat `Float32List`, zero-copy vector views, and normalization/pooling metadata. Multimodal and speculative decoding settings are rejected for embedding contexts. An opt-in checksum-pinned Apache-2.0 MiniLM GGUF test covers real model inspection, persistent and one-shot embeddings, deterministic output, normalization, and semantic ranking without bundling weights. |
| Native reranking | Experimental | `LlamaReranking.scorePair`, `scoreDocuments`, and `LlamaReranker` use upstream rank pooling with rerank prompt formatting and configurable special-token parsing. `LlamaReranker` validates and snapshots candidate chunks before native scoring. Multimodal and speculative decoding settings are rejected for reranking contexts. An opt-in checksum-pinned Apache-2.0 Jina tiny reranker test covers real pair scoring, same-context batches, deterministic semantic ordering, and RAG candidate reordering without bundling weights. |
| Multimodal | Experimental | Matching `mmprojPath` files load through pinned upstream `mtmd`. Image/audio file and encoded-byte parts are preprocessed in the worker isolate, context info reports model-specific vision/audio support, and each request is bounded to 64 inputs of at most 64 MiB each. Non-causal media chunks are checked against the physical ubatch before decode and fail with a typed generation error when the configured ubatch is unsafe. Opt-in checksum-pinned TinyGemma3 CIFAR and official Qwen3 ASR fixtures cover real model/mmproj loading, deterministic file/byte image classification and audio transcription, telemetry, and cleanup. Video stays unsupported because upstream's helper requires external ffmpeg tools. See [multimodal.md](multimodal.md). |
| LoRA | Experimental | `LlamaEngine` can load, list, globally scale, and unload upstream LoRA adapters by opaque id. `GenerationConfig.loraScales` can select an exact adapter/scale set for one request; `null` uses global scales and an empty map disables all adapters. Worker cleanup restores global scales after success, cancellation, or failure. An opt-in checksum-pinned MIT base/adapter pair verifies real load, observable generation changes, scale zero/one, request disable and restoration, unload, and baseline recovery. See [lora.md](lora.md). |
| Speculative decoding/MTP | Experimental | `NGramSpeculation` exposes pinned upstream `ngram-simple`, `ngram-map-k`, and `ngram-map-k4v`; `NGramModSpeculation` exposes configurable match/minimum/maximum draft lengths; and request-local `NGramCacheSpeculation` uses an in-memory cache without unsafe external cache files. Synthetic drafts plus weighted output/state equivalence cover all five draftless strategies. `DraftModelSpeculation`, `Eagle3Speculation`, `DFlashSpeculation`, and `MtpSpeculation` use the same `common_speculative` layer, including integrated or separate MTP heads, strategy compatibility checks, cooperative draft-context cancellation, rejected-tail removal, configurable draft limits, and composite state snapshots. `LlamaModelInfo.nextnLayerCount` exposes model MTP metadata. Model-backed speculation cannot share an mmproj context, and media-bearing requests reject every speculative strategy. Stop-string or stop-token requests fall back to ordinary decoding. Opt-in checksum-pinned fixtures verify ordinary TinyLlama draft-model, Qwen3 1.7B EAGLE-3, and integrated Qwen3.5 MTP output equivalence, accepted-token telemetry, and cleanup. DFlash has configuration/native validation but remains upstream-dependent because no compatible fixture is pinned here. |
| Native-assets packaging | Experimental | A CMake-backed build hook emits a bundled `llama_dart_bridge` code asset for Dart/Flutter native-assets builds. Linux and Windows native x64/arm64 policies default to strict Vulkan, accept an explicit CPU-only override and optional pinned SDK root, and reject unsupported/cross-architecture builds. Android accepts an explicit Vulkan variant using package-pinned Vulkan-Hpp plus the Flutter-selected NDK's target loader, SPIR-V headers, and host `glslc`; no app-specific SDK path is required. Its hash-gated build-output overlay sets `GGML_VULKAN_ANDROID_SAFE_QUANT=1` and `GGML_VULKAN_ANDROID_SAFE_K_QUANT=1` only for that variant. Windows consumes the native-assets Visual Studio environment and exact compiler/linker/archiver through Ninja. Model-free policy tests pass on macOS; Linux/Windows compilation and runtime evidence remain pending. Host smoke coverage exists, supported-ABI Android CPU debug and release APK packaging pass from `example/`, Android arm64-v8a and x86_64 Vulkan bridge cross-compiles pass, and a final-source arm64 Debug harness on an Adreno 750 passed a bounded CPU-oracle, cancellation/reset/recovery, and repeat-dispose gate. It remains a single device/model-class receipt, not a release, performance, or full-operation-offload claim; the strict intermediate-result checker is still not clean. The bridge also cross-compiles directly for iOS 15 arm64 with embedded Metal. A dependent Flutter app passes an iOS 26.5 Simulator automatic-backend runtime regression and an unsigned `iphoneos` Debug build; physical-device Metal runtime testing remains pending. |
| Examples | Experimental | `example/dart_cli/chat.dart` demonstrates local chat with an app-supplied GGUF model, `embeddings.dart` exercises real flat batch embeddings, `local_rag.dart` demonstrates model-free local RAG primitives, and image/audio CLIs exercise matching mmproj files. The mobile-first Flutter `example/` selects app-owned GGUF/mmproj/image files, loads and unloads an engine, streams cancellable text/image chat, resets full-history context, and reports capabilities and telemetry while also validating native-assets packaging. |
